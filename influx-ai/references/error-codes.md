# 错误码与状态参考

本文汇总达人发现与邮件建联的错误处理。下方达人发现说明不套用于邮件；邮件错误码与重试边界见「[邮件建联错误与重试](#邮件建联错误与重试)」，部分成功及状态见 [API 参考](api-reference.md#邮件建联接口)。

influx-ai 调用 Scout OpenAPI，每次请求都通过 `X-API-Key` 头携带 `SCOUT_API_KEY` 认证。返回统一为 `success / data / error / meta` 包装。
判断成功要分两层：先看顶层 `success`，再看 `data.status` 与 `data.errors`（协议调用成功 ≠ 检索业务成功）。

## 顶层错误码（error.code）

Scout 的外层 `error.code` 约定为 `HTTP 状态码 * 100 + 1`。本轮认证、402 积分、429 限流和计费回执说明仅针对自然语言搜索、相似达人及四平台结构化列表六个接口，不扩展品牌合作、实时提及或邮件契约。常见：

| error.code | HTTP | 含义 | 处理 |
|------|------|------|------|
| 40001 | 400 | 请求无效（如主页链接不支持、平台不一致） | 核对入参 |
| 40101 | 401 | 认证失败：`SCOUT_API_KEY` 缺失、无效、过期或已撤销 | 提示用户配置或更新 `SCOUT_API_KEY`（通过 `X-API-Key` 头发送）。不要重试，直到凭据修复 |
| 40201 | 402 | 六个达人检索接口中，`error.message=insufficient_credits` 表示积分不足 | 提示检查钱包余额；其他 402 保留原错误，不一概解释成积分不足；Skill 不计算或执行扣费 |
| 40301 | 403 | 授权失败：上述六接口可能被 Key scope、服务端策略、用户权限或资源归属拒绝 | 检查 `creator:search` 和用户 `Scout Discover` 权限，不统一解释成缺套餐，**不要自动重试** |
| 40401 | 404 | 资源未找到（如相似达人种子未被 Scout 收录），或异步任务不属于当前 Key 所解析的用户 | 告知用户更换种子/参数；若是异步任务（实时提及）返回 404，说明该 `task_id` 由其他用户创建，换回创建它的那把 Key 才能查询 |
| 40901 | 409 | 歧义（如仅用户名解析到多个平台） | 请用户补充平台 |
| 42201 | 422 | 请求参数校验失败（字段名/类型/取值/未知字段） | 核对字段名与结构；**出现 `Unknown field` 说明传了接口不支持的字段** |
| 42901 | 429 | 上述六接口受到限流 | 有有效 `Retry-After`（非负整数秒或有效 HTTP 日期）时按其提示等待；缺失或无效就不编造时间，不自动重试，不更换 Key 绕过限流 |
| 50001 | 500 | 服务端内部错误 | 记录 `meta.request_id`，据实告知"暂时不可用"，不要编造结果 |
| 50301 | 503 | 服务或依赖暂时不可用（如认证、策略、限流依赖或种子查询） | 如实说明暂不可用，不解释成 Key 一定无效，不自动重试 |

> 脚本在 HTTP 错误或 `success:false` 时以非零状态退出，并在标准输出保留完整响应、标准错误写错误摘要。

## 已知的接口特定错误

| 场景 | 表现 | 说明 |
|------|------|------|
| 品牌合作 · TikTok | 一般正常返回 | 早前因 Scout 原生品牌合作 TikTok 聚合查询的 GROUP BY 缺陷（provider 侧 BRAND-001）会返回 HTTP 500 / `error.code 50001`，**现已修复、可正常检索**。若仍偶发 500，按内部错误处理、如实说明，不要当作"没有达人"。 |
| 自然语言搜索 · 传了不支持的字段 | `42201 ... Unknown field` | 如 `seed_creators` 在未部署该能力的旧实例、或把时间窗/语言当作品牌合作入参。核对字段是否属于该接口。 |

## data.status 业务状态（自然语言搜索 / 相似达人）

顶层 `success:true` 只表示调用完成，务必再看 `data.status`：

| data.status | 含义 | 处理 |
|------|------|------|
| `success` | 正常返回候选 | 正常展示 |
| `empty` | 无候选命中 | 如实说明没有结果，询问是否放宽条件；不要静默转网页搜索 |
| `partial` / `router_degraded` | 结果不完整 / 本次检索方式可能非最优 | 说明结果不完整；`router_degraded` 时提示"可能不是最优检索方式" |
| `invalid_request` / `intent_parse_failed` / `intent_conflict` / `condition_unsupported` / `routing_failed` / `failed` | 检索业务失败 | 结合 `data.errors` 说明，不要报告为成功 |

> 这些失败状态下脚本也会以非零状态退出。`partial` / `empty` / `router_degraded` 不是完整命中，展示时要据实说明。

## 结构化列表 · total 语义

结构化列表（`list_creators.mjs`）的 `data.total` / `data.pages` / `meta.total` **仅当本次查询激活 2 个以上原生筛选条件时才返回数值，否则为 `null`**。`null` 不代表 0 条，只表示未计算精确总数。不要把 `null` 解释成"没有结果"或"全部"。

## meta 字段

- `meta.request_id`：排查用，出现 50001 等内部错误时记录并反馈。
- `meta.total`：业务展示总量，具体语义依接口而定；结构化列表受上面的 total 语义约束，不能用于计算费用。

自然语言搜索、相似达人与四平台结构化列表六个接口已接入积分，以下说明不套用于品牌合作、实时提及或邮件接口。

| 字段 / 状态 | 含义与处理 |
|------|------|
| `meta.billing_operation_id` | 本次独立计费操作号，不是 `request_id`；核对本次用量时保留 |
| `meta.billing_status=pending_settlement` | 业务结果已交付，积分仍待结算；不代表业务失败 |
| `meta.credits_consumed=null` | 尚未取得已结算积分数，不是扣了 0；不将空值转换为 0 |
| `meta.credits_remaining` | 待结算时是准入检查余额，不是扣款后的余额；`-1` 表示未提供，不表示无限 |
| `meta.billable_units` | 本次实际交付的计费项数，不是价格或已扣积分 |
| `meta.billing_status=recording_failed` | 用量登记失败，需要核对；不代表业务查询失败或免费 |

自然语言 / 相似按 `limit`、结构化列表按 `size` 做最高可能用量准入；实际登记成功或部分成功交付的候选数 / 当前页 `items` 数。不能用 `total` 或请求数量作为最终扣费数量。`pending_settlement` 或 `recording_failed` 不触发重复搜索。重新执行会产生新的独立计费操作，不能代替查询原回执；价格与扣费由后端 Billing 负责，Skill 不自行计算或执行扣费。记录并保留 `billing_operation_id` 和 `request_id`，不新增查询回执接口。缺失计费字段不能推断免费。

> `service_level`（S1/S2/S3）在结构化列表里裁剪返回字段，在其它链路仅写入 meta（见 [平台参数](platform-params.md) 与 [达人搜索子 Skill](../discovery/creator-search/SKILL.md)「服务等级与 lang」）；不能据此推算积分价格，非法等级返回 `40001`。

## 认证与身份（X-API-Key）

- 每次请求都必须带 `X-API-Key: <SCOUT_API_KEY>`。脚本在缺少 `SCOUT_API_KEY` 时**在本地直接报错退出**，不会发出请求。
- 用户身份由后端根据 Key 解析，**无需**再传用户 ID，也不使用 `X-User-Identity`。
- 仅带 JWT、不带 Key 无法通过这些入口的认证。
- 自然语言搜索、相似达人及四平台结构化列表共六个接口要求 `creator:search`。后端分别检查 Key 有效性、Key scope、服务端 scope 策略和用户 `Scout Discover` 权限；有 scope 不等于有业务权限。不需要 JWT、用户 ID、自报角色或额外 scope 请求头，普通搜索无需 `billing:read`，Skill 不自动创建 Key。目标环境需确认策略启用、用户权限和钱包可用；是否限流及阈值以实际配置为准。
- 达人发现覆盖的 `/openapi/v1/creators/**` 与 `/openapi/v1/brand-discovery/**` 共 10 个操作统一要求 `creator:search` scope（搜索、列表、相似达人、品牌合作，以及实时提及的提交/状态/结果）。
- **异步任务归属**：实时提及任务归创建它的用户所有。换一把属于其他用户的 Key 去查询 `task_id` 会返回 `404`（见上表）；同一用户换 Key 后仍可查询。
- Key 属于机密：不要写入文档、源码、命令参数或日志；多用户场景各自使用自己的 Key。

## 邮件建联错误与重试

以下仅适用于邮件七项操作；执行确认与发送边界见 [邮件子 Skill](../outreach/creator-outreach/SKILL.md#安全规则)，邮件响应与状态见 [API 参考](api-reference.md#邮件建联接口)。

正常错误 code 为 `HTTP × 100 + 1`，不是 HTTP 本身或内部字符串标识。不按 message 固定文案分类。

| HTTP | code | 含义和处理 |
| --- | --- | --- |
| 400 | 40001 | 业务/邮件参数拒绝，检查请求，不自动改目标 |
| 401 | 40101 | Key 缺失/无效/过期/撤销，检查受保护配置 |
| 402 | 40201 | 业务用例返回的支付/业务错误，不代表邮件余额不足；legacy 不因缺新 `creator.outreach` 权益触发 |
| 403 | 40301 | scope、用户、权益或资源权限拒绝，不能断言只是缺 scope |
| 404 | 40401 | 不存在或不可见，核对已有引用 |
| 409 | 40901 | 状态/幂等冲突，不自动覆盖或换键 |
| 422 | 42201 | DTO 类型、长度、未知字段或组合校验失败 |
| 429 | 42901 | 限流/配额，合法 Retry-After 可展示，不自动重发 |
| 500 | 50001 | 内部故障，提交结果可能未知 |
| 502 | 50201 | 邮件上游认证、权限、网络或契约故障，不等于用户 Key 错误；提交结果可能未知 |
| 503 | 50301 | 依赖不可用或可信身份资料不足，不改环境/邮箱绕过 |

Billing 行为依赖 `billing.backend`：Key 和 scope 始终校验，legacy 不检查新账本 `creator.outreach` 权益，influxai 模式才额外校验，相关拒绝可能返回 403 或依赖故障 503。业务用例仍可能通过 402 返回自己的支付/业务错误。429 的 Retry-After 仅在下游提供有限非负值时由服务端取整返回，配额拒绝可没有该头，不编造时长。

没有 JSON 外壳的中断、超时、网关 HTML、未知 HTTP 或外壳不一致是本地传输/协议异常，保留已有 HTTP，不伪造后端码。涉及提交时保留结果未知，不自动重试或换键。合法 4xx 拒绝只说明当前请求被拒绝，不证明此前操作未发生。错误输出仅含安全类别、消息、已有状态码、诊断号及重试建议，不转储原始报文或请求头。
